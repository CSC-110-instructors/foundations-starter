# CSC110 Foundations Path | Learning by Crafting Rubric

## Learning goals

Deepen your understanding of two CSC110 topics by designing materials that help others learn them. Write a homework assignment with a working Python solution, and design an in-class activity that helps learners practice a different concept and gives an instructor a way to recognize and address misconceptions.

## Points at a glance

| Component | Points |
|---|---:|
| Homework assignment | 12 |
| In-class activity | 12 |
| Planning, prototypes, and submission | 6 |
| **Total** | **30** |

Demo Day participation is required. The final exam is graded separately.

## 1. Homework assignment · 12 points

| Criterion | Full-credit evidence | Points |
|---|---|---:|
| **1.1 Learning outcomes and alignment** | The assignment states measurable outcomes using observable verbs. The tasks give students a clear opportunity to demonstrate those outcomes using the chosen CSC110 topic. | 2 |
| **1.2 Student instructions** | The instructions follow the style of CSC110 homework. A student can tell what to do, what the finished program should do, and which parts they are responsible for completing. | 2 |
| **1.3 Scope and room for different solutions** | The task is appropriate for an introductory Python student and allows more than one reasonable approach. A typical solution requires roughly 20–30 lines of student-written code, excluding comments and docstrings. Judge the scope of the task and allow reasonable variation in solution length. | 2 |
| **1.4 Starter code** | A separate starter file provides the scaffolding students need. It matches the written instructions, makes clear what students should implement, and marks where they should write docstrings. | 2 |
| **1.5 Example solution** | The example solution runs with the supplied files, completes the stated tasks, and behaves as described in the instructions for representative inputs. It demonstrates one valid way to apply the target concept. | 2 |
| **1.6 Code clarity and documentation** | The example solution is readable, includes useful comments, and provides a docstring for every function. Any copied code is marked and cited next to the block and in the references at the top of the file. The author can explain how any imports support the assignment. | 2 |

## 2. In-class activity · 12 points

| Criterion | Full-credit evidence | Points |
|---|---|---:|
| **2.1 Learning goals and alignment** | The activity states clear learning goals for a CSC110 topic different from the homework topic. The exercise gives students a clear opportunity to practice and demonstrate those goals. | 2 |
| **2.2 Active practice** | Students do meaningful work with the concept, such as tracing code, explaining a result, or comparing approaches. The steps build toward the learning goals and make sense for an introductory class. | 2 |
| **2.3 Targeted misconceptions** | The activity addresses the two mistakes or misconceptions identified for its topic. The prompts or steps make those mistakes visible and give students a way to examine or correct their reasoning. | 2 |
| **2.4 Instructor guide** | The guide includes the learning goals, materials list, and a sequence an instructor can follow from setup through wrap-up. It makes clear what the instructor and students do at each stage. | 2 |
| **2.5 Student materials** | The slides, handout, worksheet, manipulative, or other materials are accurate, clear, and ready to use. They match the instructor guide and provide what students need to complete the exercise. | 2 |
| **2.6 Evidence of learning** | The guide explains what to look or listen for in student responses or actions. It helps the instructor distinguish an accurate explanation from a response that still shows a targeted misconception. | 2 |

## 3. Planning, prototypes, and submission · 6 points

| Criterion | Full-credit evidence | Points |
|---|---|---:|
| **3.1 Proposal and design** | The proposal identifies two eligible topics, with two possible homework outcomes and two possible misconceptions for each. The design selects different topics for the two artifacts, outlines the homework task and its three or four subtasks, and describes at least two activity prompts or steps. It includes the GitHub screenshot showing at least two commits. | 2 |
| **3.2 Prototype development** | Prototype I shows a working draft of the homework’s core task and a first version of the activity’s main exercise. Prototype II provides near-complete drafts of both artifacts that someone else can follow, including the homework instructions, starter code, and solution draft or outline, and the activity guide and student materials. | 2 |
| **3.3 Final repository and README** | The GitHub repository submitted through Gradescope contains both artifacts and the files needed to run the code and use the activity. The README lists the homework outcomes and the misconceptions addressed by the activity and explains how to run the code and find the activity materials. Include a digital copy or reproduction instructions for any physical materials. | 2 |
