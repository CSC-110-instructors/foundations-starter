# CSC110 Final Activities | Foundations Path

The **Foundations** path ends with two individual components: a _final examination_ and a _Learning by Crafting_ activity. 

The _final exam_ will be similar in style and structure to the midterm exam. The exam is take home, open note, and untimed. It will be given as a Moodle quiz, and will open on the evening of Monday, December 14th, 2026. The exam period will close on **Tuesday, December 22, 2026, at 3:00 p.m.** 

For _Learning by Crafting_, you’ll design two resources for a future CSC110 class: 

1. a homework assignment
2. an in-class activity. 

Choose topics you found challenging. Writing instructions, anticipating common mistakes, and working through your own materials will help you strengthen your understanding and prepare for the final exam.

Complete both components individually. The deadlines and submission instructions below are for Learning by Crafting.

## What you’ll create

| Artifact | What to include |
|---|---|
| **Homework assignment** | Student instructions in the style of CSC110 homework, measurable learning outcomes, starter code that shows where students should write docstrings, and a complete example solution. |
| **In-class activity** | An instructor guide with learning goals, a materials list, and directions for running the activity. Include the materials students will use, such as slides, a handout, a worksheet, or a physical manipulative. |

Design the homework so students can solve it in more than one way. Aim for a task a typical CSC110 student can complete by writing **20–30 lines of code**, excluding comments and docstrings. Comment your example solution and write a docstring for every function in it.

Choose a **different topic** for the in-class activity. Give students something to do with the concept, such as tracing a loop, explaining why a function behaves unexpectedly, or comparing two approaches. Design the activity so the instructor can see what students understand and where they are getting stuck.

Use GitHub to track your work. You may use additional imports, algorithms, or modules if you can explain how they support the assignment. If you copy a block of code, mark its boundaries with comments, cite the original source next to the block, and include the source in the references at the top of the file.

## Proposal

Use the proposal template and submit `[Name]_LearningActivitiesProposal.pdf`, replacing `[Name]` with your name.

Propose two topics from this list: **functions, conditionals, loops, nested loops, strings, and lists**. For each topic, include:

- Two possible learning outcomes for a homework assignment. Use observable verbs from Bloom’s Taxonomy, such as *trace*, *write*, or *debug*.
- Two common mistakes or misconceptions an in-class activity could help students recognize and address.

## Design

Submit `[Name]_LearningActivitiesDesign.pdf`. Include:

- **Topic choices.** Identify which topic you’ll use for the homework and which you’ll use for the in-class activity.
- **Homework plan.** Describe the overall task and the three or four smaller tasks students will complete to accomplish it.
- **Activity plan.** Describe what students will do, outline at least two prompts or steps, and explain how they will help surface or address the mistakes or misconceptions you identified.
- **GitHub progress.** Include a screenshot of your repository, created through the final project assignment on GitHub, showing at least two commits. Edits to Markdown files count.

## Prototypes and final submission


For each prototype and the final submission, commit and push your work to GitHub, then submit your repository through the corresponding Gradescope assignment. Your repository should contain the current versions of both artifacts, all files needed to run your code, and a `README.md`. Use the README to list the homework learning outcomes and the mistakes or misconceptions addressed by the activity. Explain how to run the code and where to find the activity materials.

Keep the starter code (for example, `[Name]_HW.py`) separate from the example solution. Include any supporting Python files, images, or other materials. If your activity uses a physical manipulative, include a digital copy or enough information for an instructor to reproduce it.

| Milestone | What to submit |
|---|---|
| **Prototype I** | A working draft of the homework’s core task and a first version of the activity’s main exercise or prompts. Include a brief outline of how the instructor will run the activity. |
| **Prototype II · Homework** | Submit a near-complete draft with the learning outcomes, full student instructions, draft starter code, and a draft or detailed outline of the example solution. A reader should be able to follow the assignment from start to finish. |
| **Prototype II · In-class activity** | Submit a near-complete draft with the learning goals, materials list, step-by-step instructor guide, and draft student materials for each step. Include notes on what student responses or actions would reveal about the misconceptions you identified. A reader should be able to walk through the activity from start to finish. |
| **Demo Day** | Bring a near-complete version of your materials. Be ready to show how students would get started on the homework or walk through part of the activity. |
| **Final submission** | The complete homework instructions, learning outcomes, starter code, and working example solution. Include the finished instructor guide, student materials, README, and supporting files. |
